# Формат пакета задачи (format_version 1)

Документ написан так, чтобы его одинаково удобно читали человек и языковая модель. Строгое описание полей лежит в [`schemas/problem.schema.json`](schemas/problem.schema.json), проверить пакет можно командой:

```bash
pip install pyyaml jsonschema
python tools/validate_problem.py problems-examples/sum-of-two
```

Готовые примеры: [`problems-examples/`](../problems-examples).

## 1. Что такое пакет

Пакет задачи это папка (или zip-архив этой папки) с обязательным файлом `problem.yaml`:

```
my-problem/
├── problem.yaml            # описание: тип, лимиты, группы тестов, чекер (обязательно)
├── statement/
│   ├── ru.md               # условие на русском (Markdown + формулы $...$)
│   └── images/             # картинки, на которые ссылается условие
├── tests/
│   ├── small01.in          # вход
│   ├── small01.out         # эталонный ответ (если нужен)
│   └── ...
├── checker/check.cpp       # собственный чекер (если checker.type = custom)
├── interactor/interactor.cpp  # интерактор (если type = interactive)
├── validator/validate.cpp  # проверка корректности входов (необязательно)
└── solutions/              # эталонные и заведомо неверные решения для самопроверки
```

Задачи без запуска кода (`choice`, `text_answer`) не нуждаются в `tests/`, чекере и интеракторе: всё описано в `problem.yaml`.

## 2. Типы задач

| `type` | Что делает ученик | Что обязательно в `problem.yaml` |
|---|---|---|
| `batch` | Сдаёт программу, она читает вход и пишет ответ | `test_groups`, `checker` |
| `interactive` | Сдаёт программу, которая общается с интерактором | `test_groups`, `interactor` |
| `output_only` | Присылает готовый файл ответа вместо программы | `test_groups`, `checker` |
| `choice` | Выбирает варианты ответа | `questions` |
| `text_answer` | Вводит короткий ответ текстом или числом | `answers` |

## 3. `problem.yaml`: справочник полей

### 3.1. Общие поля

| Поле | Обяз. | Описание |
|---|---|---|
| `format_version` | да | Всегда `1` |
| `slug` | да | Стабильный идентификатор: латинские буквы в нижнем регистре, цифры, дефис (`sum-of-two`) |
| `title` | да | Названия по языкам: `{ ru: "Сумма двух чисел" }` |
| `statement` | нет | Пути к условиям по языкам. По умолчанию `statement/<язык>.md` для каждого языка из `title` |
| `type` | да | См. раздел 2 |
| `tags` | нет | Список тегов |
| `difficulty` | нет | Целое от 1 до 10 |
| `languages` | нет | Разрешённые языки (`python`, `c`, `cpp`). Не указано: все включённые в системе |
| `io` | нет | Режим ввода-вывода (3.2) |
| `limits` | нет | Ограничения (3.3) |
| `submission` | нет | Правила приёма решений (3.4) |
| `checker` | зависит от типа | Проверка ответов (раздел 5) |
| `interactor`, `validator` | зависит от типа | `{ path: ..., language: cpp }` |
| `feedback` | нет | Что видит ученик (раздел 7) |
| `test_groups` | зависит от типа | Группы тестов (раздел 4) |
| `questions`, `answers` | зависит от типа | Для `choice` и `text_answer` (раздел 8) |
| `solutions` | нет | Решения для самопроверки (раздел 9) |

### 3.2. `io`

```yaml
io: { mode: stdio }                                   # по умолчанию
io: { mode: files, input: input.txt, output: output.txt }
```

В режиме `files` решение читает и пишет файлы с указанными именами в рабочей папке запуска. Для `interactive` всегда используется `stdio`.

### 3.3. `limits`

```yaml
limits:
  time_ms: 1000        # время процессора на один тест
  memory_mb: 256
  output_kb: 1024      # размер вывода
  per_language:
    python: { time_multiplier: 3, memory_multiplier: 2 }
```

- Любое поле можно опустить или задать `null`: тогда **ограничения именно этой задачи нет**. Лимиты не отключаются целиком: системные жёсткие потолки (время, wall-time, память, размер вывода, число процессов, диск) действуют всегда. Их значения задаются в конфигурации воркера.
- Лимиты **примерные**: время измеряется как CPU-время песочницы, а wall-time служит страховкой от зависаний.
- Итоговый лимит для языка = базовый лимит × множитель языка из профиля языка × `per_language` задачи.

### 3.4. `submission`

```yaml
submission:
  allow_archive: true      # можно прислать zip с несколькими файлами
  entry: main.py           # точка входа для интерпретируемых языков, по умолчанию main.py
  max_archive_kb: 1024
  max_files: 20
```

Правила для многофайловых решений:
- **C и C++:** компилируются все исходники архива (`*.c` / `*.cpp`), заголовки берутся из архива.
- **Python:** запускается файл `entry`, остальные модули доступны для импорта.
- Произвольные сборочные скрипты (Makefile и т.п.) от учеников **не поддерживаются** намеренно.
- Пути внутри архива проверяются (запрещены `..`, абсолютные пути, ссылки), размер распаковки ограничен.

## 4. Группы тестов

```yaml
test_groups:
  - name: samples
    tests: "tests/sample*.in"
    points: 0
    visibility: open
    show_in_statement: true
  - name: small
    tests: "tests/small*.in"
    points: 40
    scoring: sum
  - name: large
    tests: ["tests/large*.in"]
    points: 60
    scoring: all_or_nothing
    depends_on: [small]
```

| Поле | По умолчанию | Описание |
|---|---|---|
| `name` | обязательно | Латинские буквы, цифры, `_`, `-`; уникально внутри задачи |
| `tests` | обязательно | Маска (или список масок) входных файлов. Каждый вход имеет расширение `.in` |
| `points` | `0` | Баллы группы |
| `scoring` | `sum` | Правило подсчёта (ниже) |
| `visibility` | `hidden` | `open` или `hidden` (раздел 7) |
| `depends_on` | пусто | Группы, которые должны быть пройдены полностью |
| `show_in_statement` | `false` | Вставить тесты группы в условие как примеры |
| `feedback` | как у задачи | Переопределяет политику показа для этой группы |

Правила:
- Файлы внутри группы упорядочены по имени.
- Ответ к `name.in` лежит в `name.out` в той же папке. Он обязателен для чекеров `exact`, `tokens`, `float`. Для `custom` и интерактивных задач ответа может не быть (чекер получает пустой файл).
- **Один тест не может входить в две группы.** Следите за масками: `s*.in` захватит и `sample01.in`, и `small01.in`.
- `scoring`:
  - `sum`: баллы группы делятся поровну между тестами, ученик получает долю за каждый пройденный тест;
  - `all_or_nothing`: баллы только если пройдены все тесты группы;
  - `min`: зарезервировано под чекеры с частичными баллами; в версии 1 ведёт себя как `all_or_nothing`.
- `depends_on`: если зависимость пройдена не полностью, тесты группы не запускаются, их вердикт `SKIPPED`, баллов за группу 0. Циклы запрещены.
- Результат посылки: сумма баллов групп. Вердикт `OK`, если набраны все баллы (или пройдены все тесты, когда баллов нет), иначе вердикт первого неудачного теста или `PARTIAL`, если баллы есть, но не все.

## 5. Чекеры

| `checker.type` | Сравнение |
|---|---|
| `exact` | Построчно; пробелы в конце строк и пустые строки в конце файла игнорируются |
| `tokens` | По токенам, разделённым пробелами и переводами строк |
| `float` | Как `tokens`, но числа сравниваются с точностью `eps` (абсолютной или относительной); `eps` обязателен |
| `custom` | Собственная программа, `path` обязателен |

### Протокол собственного чекера (v1)

```
check <input-file> <participant-output-file> [<answer-file>]
```

- Код возврата: `0` OK, `1` WA, `2` PE (неверный формат), `3` FAIL (ошибка жюри, это не вина ученика).
- Сообщение пишется в `stderr`, длина обрезается. Ученик видит его только в рамках политики показа.
- Коды `0`, `1`, `2`, `3` и порядок аргументов совпадают с testlib. Чекеры, которым достаточно этих кодов, переносятся почти без изменений. Частичные баллы пока не поддерживаются.
- Чекер запускается в песочнице; вывод ученика считается недоверенными данными.

### Протокол интерактора (v1)

```
interactor <input-file> [<answer-file>]
```

- `stdin` и `stdout` интерактора соединены с `stdout` и `stdin` решения.
- Вердикт и сообщение: как у чекера (код возврата и `stderr`).
- Падение или превышение лимитов самого решения фиксирует система (RE, TL, ML), приоритет у ошибки решения.
- Файлы тестов и ответы лежат только на стороне жюри, решению они недоступны.

## 6. Вердикты и расшифровки

| Код | Значение для ученика |
|---|---|
| `OK` | Тест пройден |
| `WA` | Неверный ответ |
| `PE` | Неверный формат вывода |
| `TL` | Превышено время |
| `ML` | Превышена память |
| `RE` | Ошибка выполнения (для Python показывается тип ошибки и строка) |
| `CE` | Ошибка компиляции (показывается очищенный вывод компилятора без путей сервера) |
| `OL` | Слишком большой вывод |
| `PARTIAL` | Часть баллов (на уровне посылки) |
| `SKIPPED` | Тест не запускался: не пройдена зависимая группа |
| `IE` | Внутренняя ошибка системы, обратитесь к преподавателю |

## 7. Видимость и показ результатов

Два независимых механизма:

1. **`visibility`** группы (и теста) определяет, можно ли ученику увидеть *содержимое* теста: `open` или `hidden`. Преподаватель видит всё всегда.
2. **`feedback`** определяет, что ученик узнаёт о результатах:

| `feedback` | Ученик видит |
|---|---|
| `full` | Вердикт, время и память по каждому тесту |
| `first_fail` | Вердикт посылки и номер первого непройденного теста |
| `groups_only` | Баллы по группам тестов |
| `verdict_only` | Только вердикт посылки и итоговые баллы |

Тесты из `open`-групп ученику показывается всегда полностью (вход, ответ, вывод его программы). Для `hidden`-групп содержимое не показывается ни при какой политике. «Все открытые» или «все закрытые» достигается заданием `visibility` у всех групп.

## 8. Задачи без кода

### `choice`

```yaml
questions:
  - id: q2
    text: "Какие из выражений истинны?"
    options:
      - { id: a, text: "`7 // 2 == 3`" }
      - { id: b, text: "`7 % 2 == 1`" }
      - { id: c, text: "`2 ** 3 == 6`" }
    correct: [a, b]
    points: 2
    explanation: "`2 ** 3` равно 8."
```

Вопрос засчитывается, только если выбранное множество вариантов равно `correct`. Если верных несколько, интерфейс показывает флажки, иначе переключатель.

### `text_answer`

```yaml
answers:
  - id: a1
    text: "Что выведет `print(sum(range(5)))`?"
    accept: ["10"]
    match: number       # exact | normalized | regex | number
    eps: 0.000001
    points: 1
```

`normalized`: без учёта регистра, пробелы по краям и повторные пробелы схлопываются. `exact`: точное совпадение. `regex`: полное совпадение с регулярным выражением. `number`: сравнение чисел с точностью `eps`.

## 9. Самопроверка: `solutions`

```yaml
solutions:
  - { path: solutions/ok.py, expect: OK }
  - { path: solutions/wa_int_overflow.cpp, expect: WA, note: "int переполняется" }
```

При импорте система может прогнать эти решения и сверить вердикты с `expect`. Так сразу видно, что тесты, лимиты и чекер согласованы.

## 10. Версии

- Импорт пакета создаёт **черновик** новой версии задачи с тем же `slug`. Опубликованная версия неизменяема.
- Контест всегда привязан к конкретной версии. Правка тестов не меняет результаты старых посылок.
- Идентичность версии определяется хешем содержимого пакета.

## 11. Памятка для языковой модели, которая генерирует пакет

1. Выдавай ровно файлы пакета с указанными именами; не придумывай поля, которых нет в этом документе или схеме (`additionalProperties: false`).
2. `slug`: только `[a-z0-9-]`; названия групп: только `[a-z0-9_-]`.
3. Для `batch` с `exact`/`tokens`/`float` каждому `.in` нужен `.out`. Для `custom` и `interactive` `.out` не нужен.
4. Следи, чтобы маски групп не пересекались (частая ошибка: общий префикс имён).
5. Сумма баллов групп обычно 100; группы-образцы получают `points: 0` и `visibility: open`.
6. Если у задачи несколько правильных ответов, используй `checker.type: custom`, а не `tokens`.
7. В интерактивных задачах напоминай в условии про сброс буфера вывода.
8. В условии формулы пиши как `$...$`, обязательно укажи формат входа, формат выхода и ограничения.
9. Добавь хотя бы одно верное решение и одно неверное в `solutions/` с ожидаемыми вердиктами.
10. После генерации запусти `python tools/validate_problem.py <папка>` и исправь все `error`.

## 12. Минимальный шаблон

```yaml
format_version: 1
slug: my-problem
title: { ru: "Название" }
type: batch
limits: { time_ms: 1000, memory_mb: 256 }
checker: { type: tokens }
test_groups:
  - name: samples
    tests: "tests/sample*.in"
    visibility: open
    show_in_statement: true
  - name: main
    tests: "tests/main*.in"
    points: 100
```
