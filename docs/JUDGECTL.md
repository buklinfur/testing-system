# judgectl — консоль владельца сервера

Код: [`backend/app/judgectl/`](../backend/app/judgectl). Решения: Р2, Р33–Р36 в [`MODULE_4A.md`](MODULE_4A.md);
как устроены аккаунты, пароли и 2FA — [`AUTH.md`](AUTH.md).

## Запуск и права

judgectl работает через сервисный слой **прямо с БД**, не через HTTP. Аутентификация — доступ к ОС: возможность
запустить его от `judge` с `/etc/judge/backend.env` (там `DATABASE_URL` и `JUDGE_SECRET_KEY`).

```bash
# на установке (функция j из docs/DEPLOY_WSL2.md, §3)
j() { sudo -u judge bash -c 'set -a; . /etc/judge/backend.env; set +a; cd /opt/judge; PYTHONPATH=/opt/judge:/opt/judge/backend "$@"' _ "$@"; }
j .venv/bin/python -m app.judgectl queue status

# разработчик, база judge_test
PYTHONPATH=.:backend python -m app.judgectl --help
```

* **Каждая команда — одна транзакция**: либо всё, либо ничего. Пока человек вводит пароль или код, транзакция не
  открыта.
* **Аудит:** каждое изменение пишется в `audit_log` с `actor_cli = cli:<unix-user>` (обычно `cli:judge`), а имя
  человека из `SUDO_USER` — в `details.sudo_user`. Пароли и токены в аудит не попадают.
* **Вывод:** таблица для человека; `--json` (после имени команды: `judgectl admin list --json`) — для скриптов.
  Время в таблицах — в часовом поясе `JUDGE_TIMEZONE` (по умолчанию UTC), в `--json` — всегда UTC с `Z`.
  Пароли и токены печатаются **один раз**; пачка паролей — только в новый файл 0600 (или явно в stdout).
* **Управляющие символы.** Текст, который набрали ученики или люди без особых прав (ответы, комментарии, названия,
  условия, имена), не должен управлять терминалом владельца. В таблицах, в строке ошибки и в выводе `item` / `work` /
  `comment`
  управляющие символы показываются экранированными (`core.terminal_text`): C0 (ESC ANSI-последовательностей, `\r`,
  перезаписывающий строку, BEL, …), DEL, C1 и символы направления текста (U+202E и подобные, U+2028/2029) —
  в виде `\x1b`, `\x0d`, `\u202e`. Многострочный текст (ответ, комментарий, условие) сохраняет `\n` и `\t`, ячейка
  таблицы — нет. `--json` отдаёт данные как есть (JSON сам экранирует управляющие символы).
* **Числа в аргументах** — id, номера версий, `--last` — от 1 до 2147483647 (`core.int4`, D-088); другое — неверный
  аргумент (код 2) до обращения к базе. Номер внутри текста (`#id` группы или материала, `<slug>@<версия>`) вне этих
  границ — «нет такого». Если база всё же отвергла значение, — одна строка `judgectl: the database refused a value
  (out of range or too long)` и код 1, без трассировки.
* **Коды выхода:** 0 — успех; 1 — ошибка (`judgectl: <сообщение>` в stderr, ничего не изменено); 2 — неверные
  аргументы; 130 — прервано (Ctrl-C / конец ввода). У отказов ленты (`item`, `work`, `comment`) в конце строки — постоянный код
  в скобках, тот же, что `detail` в админском API: `judgectl: … (no_audience)`.
* Необратимые команды (`delete`, `import-rollback`) просят ввести логин или id ещё раз; без терминала нужен `--yes`.
* Команды, где вводится пароль или код 2FA (`admin add`, `admin reset-password`, `admin reset-2fa`), требуют
  терминал и без него отказывают, ничего не спросив. `admin add` и `admin reset-2fa` без рабочего
  `JUDGE_SECRET_KEY` отказывают тоже до первого вопроса.

**Файлы для `judge`.** judgectl работает от `judge`, а он не читает ваш домашний каталог. Поэтому архив задачи и
`contest.yaml` удобнее отдавать через stdin (`-`): файл открывает ваша оболочка, `judge` читает уже открытый поток:

```bash
tools/pack-problem.sh problems-examples/sum-of-two | j .venv/bin/python -m app.judgectl problem import -
j .venv/bin/python -m app.judgectl contest apply - < contests-examples/practice.yaml
```

Значения в `<угловых скобках>` — плейсхолдеры: подставьте своё вместе со скобками. Если скопировать команду как есть,
bash прочитает `<логин>` как перенаправление из файла и остановится, а не создаст пользователя со словом из примера.

### admin — администраторы (только здесь, Р2)

| Команда | Что делает |
|---|---|
| `add <логин> --name "<имя>"` | Пароль вводится дважды без эха (≥ 12 символов, правила — [`AUTH.md`](AUTH.md) §3; 3 попытки, потом отказ без изменений). Админ создаётся, затем подключается 2FA: QR в терминале + строка `otpauth://…`, код из приложения (3 попытки). Если код так и не подтверждён, админ остаётся с `2FA = pending`, войти не может, команда завершается с кодом 1 и подсказкой `reset-2fa` |
| `list [--all]` | Активные админы (`--all` — и отключённые): логин, имя, **состояние 2FA** (`confirmed` / `pending` — секрет выдан, код не подтверждён / `none`), последний вход и IP, `FAILS` — неудач в текущем окне (до блокировки — 5), блокировка до |
| `reset-2fa <логин>` | Новый секрет с QR, подтверждение кодом; все сессии админа отзываются. Это же — **повтор неподтверждённого подключения** |
| `reset-password <логин>` | Новый пароль дважды без эха; сессии отзываются, блокировка снимается |
| `disable` / `enable <логин>` | Отключение отзывает все сессии |
| `delete <логин> [--yes]` | Удалить админа, созданного по ошибке, — только если у него нет следов (ниже). Подтверждение — ввести логин ещё раз; `--yes` для скриптов |
| `failures <логин> [--last N]` | Неудачи входа админа: время, вид (`password` / `totp`), IP; сколько из них идёт в счёт блокировки |
| `unlock <логин>` | Снять блокировку перебора и обнулить счётчик |

Команды группы `admin` отказывают для ученика и наоборот (с подсказкой, какой группой пользоваться).

Код TOTP, которым подтвердили подключение, второй раз не принимается: для первого входа дождитесь следующего кода.

**Удаление (`admin delete`, `user delete`, `user import-rollback`)** — только для созданных по ошибке. Отказ, если на
пользователя что-то ссылается: задачи (владелец), импортированные им версии задач, контесты (создатель), участия, посылки, запрошенные им перепроверки посылок и проверки версий задач,
записи аудита от его имени (любое действие в вебе, в том числе вход админа). Отказ перечисляет найденное и подсказывает
`disable`. Вместе с пользователем удаляются его сессии, QR-токены, неудачи входа и блокировки по его логину; логин
освобождается. В аудит пишется `user.delete` (логин, имя, роль, что удалено вместе с ним) или `user.import_rollback`.

### user — ученики

| Команда | Что делает |
|---|---|
| `add --surname <фамилия> --first-name <имя> [--login <логин>] [--name "<имя в рейтинге>"]` | Логин — заданный или `фамилия.инициал` (см. [`AUTH.md`](AUTH.md) §2), имя в рейтинге — заданное или «Имя Ф.». Сгенерированный пароль печатается один раз |
| `import <файл.csv> --out <новый-файл>` | Пачка из CSV (ниже); печатает в stderr id импорта |
| `imports` | Прошлые импорты: id, время, файл, сколько пользователей, кто запускал, откачен ли |
| `import-rollback <id> [--yes]` | Удалить всех пользователей импорта — только если никто из них не входил и ни у кого нет следов; иначе отказ со списком вошедших. Подтверждение — ввести id ещё раз. Ученики уходят из групп вместе с собой; группа, **созданная** этим импортом, удаляется, если в ней нет других учеников (и не было), она не подключена к контесту и у неё нет продлений, иначе остаётся — отчёт говорит почему (К3). Группы, существовавшие до импорта, остаются |
| `set-timezone <логин> (<пояс> \| -)` | Часовой пояс, в котором веб показывает ученику время (IANA: `Asia/Novosibirsk`, `Europe/Moscow`); `-` — очистить (тогда пояс браузера). Хранение времени не меняется (UTC). Аудит `user.set_timezone` |
| `list [--all]` | Активные ученики (`--all` — и отключённые), последний вход, `FAILS` (неудач в текущем окне, до блокировки — 10), блокировка |
| `reset-password <логин>` | Новый сгенерированный пароль (печатается один раз); сессии и QR-токены отзываются, блокировка снимается |
| `disable` / `enable <логин>` | Отключение отзывает сессии и QR-токены |
| `delete <логин> [--yes]` | Удалить ученика, созданного по ошибке, — только без следов (ниже) |
| `failures <логин> [--last N]` | Неудачи входа — для **любого** логина, в том числе несуществующего (так видно, что ученик ошибается в логине); для админа отказ с подсказкой `admin failures` |
| `unlock <логин>` | Снять блокировку логина — **любого, в том числе несуществующего** (неудачи считаются и для них); для админа отказ с подсказкой `admin unlock` |
| `unlock --ip <адрес>` | Снять блокировку IP (например, весь класс за одним школьным адресом); аудит `ip.unlock` |
| `set-login <логин> <новый-логин>` | Сменить логин (по просьбе ученика); формат как у любого логина |
| `qr-token <логин> [--no-qr]` | Одноразовая ссылка входа на 7 дней (`<JUDGE_PUBLIC_ORIGIN>/login/qr#<токен>`) и её QR; новый токен отменяет прежний. Без `JUDGE_PUBLIC_ORIGIN` печатается только токен |

#### Импорт CSV (`user import`)

* Строки: `фамилия;имя[;логин][;display_name][;класс]` — так сохраняет Excel. Кодировка определяется сама: UTF-8 с
  BOM, UTF-8, cp1251 (Excel на Windows по умолчанию); разделитель — `;` или `,`; поля в кавычках допустимы.
* Первая строка — заголовок, если в ней есть ячейка «фамилия», `surname`, `last_name`, `lastname` или `last name` (в
  любом регистре); иначе это данные. **С заголовком столбцы берутся по названиям и в любом порядке**: `фамилия`, `имя`
  (`first_name`), `логин` (`login`), `display_name` (`имя в рейтинге`), `класс` (`class`, `группа`, `group`);
  неизвестный или повторённый столбец — ошибка, `имя` обязательно. Так файл учителя «Фамилия;Имя;Класс» работает как
  есть. **Без заголовка — по позиции**, класс — только пятый столбец (`Иванов;Пётр;;;7Б`): третий столбец всегда
  логин, поэтому «Иванов;Пётр;10a» без заголовка создаст логин `10a` — для класса нужен заголовок (В4).
  Пустые строки и пустые хвостовые ячейки пропускаются.
* **Класс** (D-020): группа с таким названием (без учёта регистра) пополняется, а если её нет — создаётся. В одном
  файле может быть несколько классов. Название архивной группы — ошибка строки (разархивируйте группу или назовите
  класс иначе). Группы и состав — в аудите (`group.create`, `group.add_members`), а в записи `user.import` —
  `groups_created` и `groups_joined`.
* Пустой логин — сгенерировать; пустой display_name — «Имя Ф.». Явные логины создаются первыми, поэтому
  сгенерированный логин не займёт логин, указанный ниже в файле.
* **Атомарно:** сначала разбирается весь файл, и обо **всех** ошибках сообщается сразу с номерами строк (не то
  число полей, нет фамилии или имени, плохой или повторяющийся в файле логин, слишком длинное имя, логин уже занят
  в базе). Если ошибка хоть одна, не создаётся никто.
* **Результат** — новый файл `--out`: создаётся с `O_EXCL` (существующий не перезаписывается) и правами 0600,
  UTF-8 с BOM и `;` (Excel открывает как есть), столбцы `фамилия;имя;логин;пароль;display_name` (и `класс`, если
  он был в файле). Файл создаётся до
  изменений в базе и удаляется, если импорт не прошёл. Пароли больше нигде не хранятся: файл — единственная копия.
  `--out -` печатает то же в stdout (с `--json` — массив объектов).
* Пример: [`deploy/dev/students-30-cp1251.csv`](../deploy/dev/students-30-cp1251.csv) (30 учеников, cp1251).

```bash
j .venv/bin/python -m app.judgectl user import /var/lib/judge/<класс>.csv --out /var/lib/judge/<класс>-пароли.csv
```

### queue — очередь проверки

| Команда | Что делает |
|---|---|
| `status` | Снимок загрузки (длина очереди, воркеры онлайн, ожидание); `--json` — ещё и метрики. Все числа из одного момента |
| `reap` | Вернуть в очередь задания потерянных воркеров сейчас, не дожидаясь reaper |
| `judgements [--last N]` | Последние проверки: вердикт, первый провал, вид TL, попытки, воркер, внутренняя ошибка |
| `events [--last N]` | Журнал очереди (регистрации, `released`, `requeued`, `gave_up`; 14 дней) |
| `rejudge --submission <id> \| --contest-problem <id> [--verdicts …]` | **Устарело:** пишет в stderr новую команду и выполняет `submission rejudge --id \| --contest-problem-id` |

### worker — воркеры

| Команда | Что делает |
|---|---|
| `list` | Воркеры: состояние, возраст heartbeat, текущее задание, ядра, число проверок, capabilities |
| `token create <имя> [--caps cpu,gpu]` | Новый токен воркера (по умолчанию `cpu,problem_check`: `problem_check` — проверки версий задач, 4а.4). Токен — **последняя строка** stdout (скрипты берут его `| tail -1`), показывается один раз |
| `token revoke <имя>` | Отозвать живой токен; если такого нет — ошибка |

### problem — задачи ([`PROBLEM_IMPORT.md`](PROBLEM_IMPORT.md))

| Команда | Что делает |
|---|---|
| `import <папка> \| <файл.zip> \| -` | Импорт пакета: все проверки, затем «imported as vN (статус)» — с номером проверки воркером, если она нужна — или «already exists as vN» (то же содержимое — ничего не пишется). `-` — zip на stdin (`tools/pack-problem.sh <папка> \| …`). Отказ — все причины сразу, код 1 |
| `import … --dry-run` | Все проверки без записи: «would be imported as vN» или «already exists as vN» |
| `list [--all]` | Задачи с последней версией, её статусом и числом версий; архивные — только с `--all` |
| `versions <slug>` | Все версии: статус, время импорта, начало `content_sha256`, число файлов, в скольких контестах закреплена, из zip или из папки |
| `show <slug>[@<версия>]` | Версия (по умолчанию последняя): названия, группы (баллы, оценивание, видимость, число тестов), программы жюри и эталоны с ожидаемым вердиктом, идущая проверка и отчёт последней законченной: итог и причина, кто и сколько проверял, лог компиляции несобравшегося чекера/интерактора, таблица эталонов (ожидалось, получено, первый неудачный тест, сообщение) и история проверок |
| `recheck <slug>[@<версия>]` | Проверить версию воркером заново (D-054): «queued», при уже идущей проверке — «already queued / running» (ничего нового). Статус версии меняется только по итогу. Архивную задачу — нельзя. Аудит `problem.recheck` |
| `checks [--last N]` | Последние проверки всех версий (20 по умолчанию): версия, причина (`import`/`recheck`), итог или состояние, причина отчёта, эталоны `сделано/всего`, сбои, время |
| `archive` / `unarchive <slug>` | Архивная задача не принимает импорт и новые закрепления; контесты, где она уже есть, не меняются |

### contest — контесты ([`CONTESTS.md`](CONTESTS.md))

| Команда | Что делает |
|---|---|
| `apply <contest.yaml> \| -` | Привести контест к файлу; печатает каждое изменение или «no changes». Новый контест — `draft`. Предупреждения (например, при `open → code` снова действует старый код) — в stderr |
| `apply … --dry-run` | Показать изменения и откатить всё (в том числе созданный код и аудит) |
| `list [--all]` | Контесты: состояние, режим времени, окно, число задач и участников; архивные — с `--all` |
| `show <slug>` | Настройки, окно в `JUDGE_TIMEZONE`, **код приглашения**, задачи с версиями (и скрытые); после таблицы — `warning:` по каждой задаче, закреплённой на версии со статусом `failed` (поле `warning` строки). `--json` — та же структура, что `GET /api/admin/contests/<slug>`: `spec` в форме `contest.yaml` + `state`, `invite_code`, `rows`, `participants` |
| `publish` / `archive <slug>` | `draft`/`archived` → `published`; → `archived` (только чтение для участников) |
| `pin <контест> <метка> <версия> --rejudge \| --no-rejudge` | Закрепить другую `ready`-версию; выбор обязателен: перепроверить все посылки задачи или оставить старые результаты |
| `code regenerate <slug>` | Новый код приглашения, старый перестаёт работать |
| `participants <slug>` | Кто вошёл и когда нажал «Начать»; `VIA` — как вошёл (`code` / `group` / `open`), `ACCESS` — даёт ли это доступ сейчас (режим и текущий состав групп) |

### extension — продления сроков ([`CONTESTS.md`](CONTESTS.md) §5)

| Команда | Что делает |
|---|---|
| `add <контест> <метка> (--user <логин> \| --group <группа>) --due <время> [--reason <текст>]` | Срок задачи позже `due_at` для одного ученика или одной группы. `--due` — как в `contest.yaml`: без смещения — `JUDGE_TIMEZONE`, или с `Z` / `+07:00`; «до конца дня» — `23:59:59`. Повторно для того же ученика или группы — заменяет срок (печатает прежний; он и в аудите) |
| `list <контест> [<метка>]` | Продления: кому, до какого времени, базовый срок, причина; `--json` — время в UTC |
| `remove <id>` | Удалить продление (уже принятые посылки не меняются) |

Отказы: задача без `due_at`, срок не позже `due_at`, не ученик, архивная группа. Аудит — `contest.extension_add`
(с `replaced`), `contest.extension_remove`.

### group — группы (классы, D-020)

Группа — адресат контестов в режимах `groups` и `code_or_groups` (`access.groups` в `contest.yaml`,
[`CONTESTS.md`](CONTESTS.md) §1–§3). `<группа>` — название (без учёта регистра; среди неархивных оно уникально) или
`#id` (нужен, когда несколько архивных групп названы одинаково). Каждое изменение — в аудите (`group.create`,
`group.rename`, `group.archive`, `group.unarchive`, `group.add_members`, `group.remove_members`).

| Команда | Что делает |
|---|---|
| `create <название>` | Новая группа; пробелы по краям и двойные убираются, регистр сохраняется |
| `rename <группа> <название>` | Новое название |
| `archive <группа>` | Группа больше не даёт доступа; в stderr — контесты, к которым она подключена, и элементы ленты, где она в адресатах (`#id вид состояние название`; адресатами они остаются, но ничего не дают). Не удаляется никогда |
| `unarchive <группа>` | Вернуть; отказ, если её название уже занято другой группой |
| `list [--all]` | Группы с числом учеников и контестов; архивные — с `--all` |
| `show <группа> [--history]` | Ученики и контесты; `--history` — и убранные из группы, с датами |
| `add <группа> <логин>...` | Добавить учеников (только `student`; в архивную нельзя). Уже состоящие — в stderr. Доступ к контестам группы — сразу |
| `remove <группа> <логин>...` | Убрать: строка остаётся с `removed_at` (кто был в классе), доступ к контестам группы пропадает, свои посылки ученик видит |

Удаление ученика (`user delete`, по правилам следов) удаляет и его строки состава групп: членство — не след (В5).
Следами считаются действия админа с группами из веба (создание, изменения состава, подключение к контесту).

### item — лента класса ([`CLASSROOM.md`](CLASSROOM.md), D-059)

Элемент ленты — ручное задание (`assignment`), ссылка на контест (`contest`) или выкладка материала библиотеки
(`material`, 4в.4). Элемент — по
`id`, группа — название или `#id`, ученик — логин. Время (`--available-from`, `--due`) — как в `contest.yaml`: без
смещения — `JUDGE_TIMEZONE`, или с `Z` / `+07:00`. Баллы (`--max-points`, `--score`) — десятичное число с точкой, не
больше двух знаков после неё (`10`, `4.5`); экспонента, `NaN`, `Infinity` — отказ (D-061). Аудит — `item.*`
(CLASSROOM §7).

| Команда | Что делает |
|---|---|
| `create --kind assignment …` | Новое задание — **черновик**. Шкала обязательна: `--grading points --max-points N`, `pass_fail` или `none`; ответ `--answer text` (по умолчанию) или `mark` («сдано», работа в тетради); оценки видны `--release manual` (по умолчанию, после публикации) или `immediate`. Политики после срока — как у задач контеста (`CONTESTS.md` §4). `--body-file` — условие в Markdown (`-` — из stdin). `--comments on\|off` — пишут ли ученики в общую ветку (по умолчанию `off`; у контест-элемента только `off`, иначе `item_invalid`) |
| `create --kind contest --contest <slug> …` | Ссылка на контест. Доступа не даёт: если адресаты его не получат (группы не подключены, вход по коду), в stderr — `warning:` |
| `create --kind material --material <slug> …` | Выкладка материала (§11 CLASSROOM): `--title` необязателен, по умолчанию — название материала. У остальных видов без `--title` — код выхода 2 (неверные аргументы), как раньше у argparse. Без `--material` — `material_required`, архивный материал — `material_archived`, нет такого — `material_not_found`. Срока и шкалы у материала нет; открывает его ученикам `item_listed`, как контест-элемент |
| `create … --group G --student L` | Создание и адресаты — одной транзакцией (отказ адресата — нет и элемента) |
| `edit <id> …` | Меняются только указанные поля; `--no-due` / `--no-available-from` очищают. Другая шкала, кроме `points`, сама убирает `max_points`. После первой оценки шкала не меняется (`grading_locked`); новый срок уже принятые `late` не пересчитывает |
| `publish <id>` | Опубликовать; нужен хотя бы один адресат. С будущим `--available-from` — отложенная публикация |
| `archive <id>` / `unarchive <id>` | Убрать из ленты (ученики видят свои работы и оценки) / вернуть |
| `delete <id> [--yes]` | Удалить черновик без работ и продлений (ввести id ещё раз или `--yes`) |
| `list [--group G] [--kind K] [--state S] [--all]` | Элементы, новые сверху: черновики и опубликованные; архивные — с `--all`; `--state` — одно состояние |
| `show <id>` | Настройки, адресаты, число продлений, работы по статусам, условие, вложения (`--json` — поле `attachments`); у элемента-материала — строка `material: <slug> «название»` |
| `audience add\|remove <id> (--group G \| --student L)...` | Добавить или убрать адресатов: группа — неархивная, ученик — `student`; у опубликованного остаётся хотя бы один |
| `extension add <id> (--user L \| --group G) --due T [--reason R]` | Продление задания — как `extension add` у контестов: позже `due_at` и `available_from`, повторно — заменяет |
| `extension list <id>` / `extension remove <id продления>` | Продления элемента; `remove` продления задачи контеста отказывает с подсказкой `judgectl extension remove` |
| `attach <id> <файл> [--name N]` | Приложить файл преподавателя (CLASSROOM §10): те же правила, лимиты (`JUDGE_ATTACHMENT_MAX_MB`, `JUDGE_ITEM_ATTACHMENTS_MAX`) и аудит, что у админского API. `-` — файл из stdin, тогда `--name` обязателен (с расширением). Имя по умолчанию — базовое имя файла. Отказ (`file_type_not_allowed`, `file_content_mismatch`, `file_empty`, `file_too_large`, `duplicate_name`, `too_many_attachments`, `item_archived`) ничего не оставляет ни в базе, ни в хранилище блобов, ни в его `tmp` |
| `link <id> <url> [--title T]` | Приложить ссылку: только `http`/`https`, хранится как дана (без пробелов по краям); сервер её не открывает |
| `attachments <id>` | Файлы и ссылки элемента по порядку: id, вид, имя или URL, размер, заголовок, когда добавлено |
| `detach <id> <att>` | Убрать вложение (без подтверждения: файл можно приложить снова). Блоб остаётся, аудит хранит имя, sha256 и размер (у ссылки — URL и заголовок) |
| `attachment-order <id> <att>...` | Новый порядок: **все** id вложений элемента ровно по разу, иначе `attachment_order_invalid` |

Ссылки `[[памятка:slug]]` в тексте элемента (`--body-file`) никогда не мешают сохранению: неверная запись,
неизвестный slug и архивный материал — строки `warning:` в stderr у `create`, у `edit` со сменой текста и у `show`
(`--json` — поле `link_warnings`).

### work — работы учеников ([`CLASSROOM.md`](CLASSROOM.md) §4–§5)

Работа — пара «задание — ученик»; `work_id` и `submission_id` команды не принимают. Сдаёт только ученик (до 4б.2 —
`dev_seed --item [--text-file F] [--file F]... [--link URL [TITLE]]...`, через тот же сервис, правила, лимиты и
квоту, что у ученика; в выводе — id файлов для `work file`). Аудит — `work.grade`, `work.return`, `work.release`.

| Команда | Что делает |
|---|---|
| `list --item <id> […]` | Очередь проверки по заданию: **все** текущие адресаты и все, у кого есть работа; без работы — статус `assigned`. Столбцы: статус, `LATE` (последняя сдача с опозданием), `MISSING` («не сдано»: сдач нет и эффективный срок прошёл, с продлениями ученика), число сдач, последняя сдача, текущая оценка и опубликована ли она |
| `list […]` без `--item` | Только существующие работы по всем заданиям, новые сверху; `--missing` без `--item` — отказ (`missing_needs_item`) |
| фильтры | `--group` — **текущие** члены группы; `--status assigned\|submitted\|graded\|returned`; `--late` / `--not-late`; `--last N` (50) |
| `show <id> <логин>` | Все сдачи с текстом ответа, файлами (`file #id имя (размер)`, у текста ответа — `the text answer`) и ссылками, вся история проверки (и неопубликованные оценки), что видит ученик. Адресат без работы — `assigned` и «не сдано»; не адресат без работы — отказ (`work_not_found`) |
| `grade <id> <логин> --score N \| --pass \| --fail \| --accept` | Оценка по шкале задания (`--accept` — шкала `none`), можно и без сдачи; `--comment`; `--release` — сразу опубликовать. Неопубликованная оценка — подсказка `work release` в stderr |
| `file <id> <логин> <file_id> -o PATH [--force]` | Сохранить файл работы — загрузку ученика или текст ответа `answer.md` (id — из `work show`). Файл ищется по паре «задание — ученик» и id: файл чужой работы — `file_not_found`. Пишется через временный файл рядом с правами 0600; существующий PATH без `--force` не перезаписывается. `-o -` — в stdout, только если это не терминал (перенаправление или конвейер: judgectl работает от `judge` и может не иметь права писать в каталог владельца); двоичное в терминал не выводится никогда |
| `return <id> <логин> --comment C` | Вернуть на доработку (ученик видит сразу и может сдать заново) |
| `release <id> [<логин>...]` | Опубликовать текущие оценки всех работ задания или этих учеников: по строке на ученика — `released`, `nothing_to_release` или `already_released`; у `immediate` и `none` — отказ `release_not_needed` |

### comment — комментарии ([`CLASSROOM.md`](CLASSROOM.md) §9, D-076)

Ветки элемента ленты: **общая** (одна на элемент) и **личная** (пара «задание — ученик», `--student <логин>`).
Консоль читает как преподаватель — всё, удалённое тоже — и пишет как консоль (автор пуст, у учеников — «Преподаватель»,
в аудите — `cli:<unix-user>`). Отметок прочтения у консоли нет: во входящих только «ждёт ответа» (последний
неудалённый комментарий написал ученик), без непрочитанного; личные отметки — у админов веба (`ADMIN_API.md` §5.9).
Текст комментариев — недоверенный: в выводе экранирован (`terminal_text`), в `--json` — как есть. Аудит —
`comment.post`, `comment.delete` (без текста).

| Команда | Что делает |
|---|---|
| `list […]` | Входящие: ветки, где новее всего последний комментарий — сверху. Столбцы: ветка, элемент, название, вид (`shared` / `private`), ученик личной ветки, число комментариев и удалённых, время последнего, «ждёт ответа». `--item`; `--group` — личные ветки **текущих** членов и общие ветки элементов, адресованных группе; `--awaiting` / `--answered`; `--last N` (50, не больше 200) |
| `show <id> [--student L]` | Вся ветка по возрастанию id: время, автор (логин или `console`), тело строками `\| …`; удалённое — с пометкой `[deleted <время> by <кто>: <причина>]` и текстом. В заголовке — включены ли комментарии учеников и может ли консоль писать (иначе код). Ветки ещё нет — `no comments yet`. Личная ветка ученика, который не адресат и у которого нет ни работы, ни ветки, — `thread_not_found` |
| `post <id> [--student L] (--text T \| --file F)` | Комментарий консоли: в общую ветку (и при выключенных комментариях учеников, и в архивном элементе, кроме черновика — `not_published`) или, с `--student`, в личную ветку задания (`not_an_assignment`, `not_a_student`, `not_addressed`). `--file -` — из stdin; файл — UTF-8 до 64 КБ (иначе ошибка, без подмены символов). Тело: `comment_required`, `comment_invalid` (NUL), `comment_too_long` (> 4000 символов) |
| `delete <id> [--reason R]` | Мягкое удаление любого комментария, **без подтверждения**: ученики его больше не видят, преподаватели видят с текстом, кем и почему удалён. Причина — до 200 символов (`reason_too_long`); повтор — `already_deleted`; нет такого — `comment_not_found` |

Сообщения учеников до 4б.2 пишет только `dev_seed` (dev, `JUDGE_DEV=1`): `--item <id> --comment <текст> [--private]
[--user N]` — от `dev-student-N` через те же правила и ту же частоту (`JUDGE_COMMENT_RATE_PER_MIN`), отказ — код в
stderr и выход 1.

### material — библиотека материалов ([`CLASSROOM.md`](CLASSROOM.md) §11, D-083…D-086)

Материал — по slug или `#id`, группа — название или `#id`. Консоль читает как преподаватель: любой материал, любую
версию, архивные тоже. **Каждое изменение содержимого** — текст, файл, ссылка, удаление, порядок вложений — создаёт
новую версию, и команда печатает её номер (`material cycles: version 4`); тот же текст или тот же порядок версии не
дают (`no change, the latest version N is the same`; в `--json` — `created: false`). Название и аудитория библиотеки
меняются на месте, без версии. **slug неизменен** (`slug_immutable` в API): вместо переименования — новый материал, а
старый — в архив. Ссылки `[[памятка:slug]]` в тексте — только предупреждения (`warning:` в stderr, в `--json` —
`warnings`), сохранению не мешают. Название, текст, имена файлов, URL и slug из ссылок — недоверенный текст:
в выводе экранирован (`terminal_text`), в `--json` — как есть. Аудит — `material.*` (без текста: длина, имена, sha256).

| Команда | Что делает |
|---|---|
| `create <slug> --title T [--body-file F] [--library L] [--group G]...` | Новый материал и версия 1. slug — `a-z`, `0-9`, `-`, 2–63 символа, первым не `-` (`slug_invalid`); занят, в том числе архивным, — `slug_taken`. `--library`: `none` (по умолчанию, в Справочнике не виден ученикам), `all_students`, `groups` (группы — `--group`, только неархивные) |
| `list [--all]` / `search <текст>` | Материалы по slug (архивные — с `--all`): аудитория, число версий, архив. `search` — по названию без учёта регистра, кириллица тоже; `%`, `_`, `\` ищутся буквально |
| `show <м> [--version N]` | Последняя версия (или указанная, с пометкой `not the latest`): название, аудитория и группы, разделы, вложения (`#id file имя (размер)` / `#id link URL «заголовок»`), разрешённые ссылки текста (`ok` / `archived` / `unknown` — так видит админ) и текст. Нет версии — `version_not_found` |
| `versions <м>` | История: номер, когда, кто (пусто — консоль), длина текста, число вложений |
| `edit <м> --body-file F` | Новый текст — новая версия с вложениями последней. `-` — из stdin. `body_too_long` (> 100 000 символов), `body_invalid` (NUL) |
| `title <м> <название>` / `library <м> L` | На месте, без версии (`title_invalid`, `library_invalid`) |
| `groups <м> [G...] [--add \| --remove]` | Группы библиотеки: ровно эти (без групп — очистить), или добавить / убрать. Новая группа — неархивная (`group_archived`); уже стоящая остаётся и после архивации группы. Если аудитория не `groups`, в stderr — подсказка |
| `archive <м>` / `unarchive <м>` | Архив: только чтение (`material_archived` на любое изменение), из Справочника уходит, лента и ссылки по-прежнему открывают. Повтор — не ошибка (`already archived` / `not archived`, в `--json` — `changed: false`) |
| `attach <м> <файл> [--name N]` / `link <м> <url> [--title T]` | Новая версия с файлом или ссылкой в конце: те же правила, лимиты (`JUDGE_ATTACHMENT_MAX_MB`, `JUDGE_ITEM_ATTACHMENTS_MAX`) и отказы, что у `item attach` / `item link`; `-` — файл из stdin с `--name`. Отказ не оставляет ничего ни в базе, ни в хранилище блобов, ни в его `tmp` |
| `detach <м> <att>` / `attachment-order <м> <att>...` | Новая версия без вложения / в новом порядке. id — **последней** версии (`material show`): у каждой версии свои строки, id старой — `attachment_not_found` / `attachment_order_invalid`. Блобы остаются у старых версий |
| `file <м> <att> [--version N] -o PATH [--force]` | Сохранить файл вложения как `work file` (D-081): новый файл 0600, существующий — только с `--force`; `-o -` — в stdout, только не в терминал. Без `--version` — последняя версия |
| `where <м>` | Где используется: элементы-материалы, элементы со ссылкой, версии задач со ссылкой (`slug@v`), материалы, чья последняя версия ссылается |
| `resolve <файл>` | Ссылки текста (файл или stdin) так, как они сохранятся: по строке на slug со статусом и предупреждения. Ничего не пишет |

### section — разделы Справочника ([`CLASSROOM.md`](CLASSROOM.md) §11)

Разделы — по `id`, два уровня: раздел и подраздел. Материал может лежать в нескольких разделах и на обоих уровнях.
Аудит — `library.*`.

| Команда | Что делает |
|---|---|
| `create <название> [--parent <id>]` | Раздел в конце верхнего уровня или подраздел в конце раздела верхнего уровня (иначе `section_too_deep`; нет родителя — `section_not_found`) |
| `list` | Справочник деревом, как его видит админ: разделы по порядку, в них материалы (архивные — с пометкой), затем `in no section:`. Если есть материалы с аудиторией `none`, в stderr — сколько их |
| `rename <id> <название>` | Новое название (`section_title_invalid`) |
| `move <id> (--parent <id> \| --top)` | В конец другого раздела верхнего уровня или верхнего уровня. Раздел с подразделами — только на верхний уровень (`section_too_deep`) |
| `delete <id> [--yes]` | Удалить раздел без подразделов (`section_not_empty`); материалы из него уходят, сами остаются. Подтверждение — id ещё раз или `--yes` |
| `place <id> <м>` / `unplace <id> <м>` | Положить материал в конец раздела (архивный — `material_archived`) / убрать. Повтор — не ошибка |
| `order [--parent <id>] <id>...` / `material-order <id> <м>...` | Новый порядок разделов уровня / материалов раздела: **все** ровно по разу, иначе `order_invalid` |

Действий ученика с материалами нет (эндпоинты ученика — 4б.2), поэтому `dev_seed` для материалов ничего не делает
(D-086); комментарий ученика в общую ветку элемента-материала (если комментарии включены: `item edit <id> --comments on`)
— `dev_seed --item <id> --comment`, как у других элементов.

### submission — посылки

| Команда | Что делает |
|---|---|
| `list [--contest <slug> [--label <метка>]] [--problem <slug>] [--user <логин>] [--group <группа>] [--verdicts WA,TL] [--status …] [--late \| --not-late] [--last N]` | Последние посылки (50 по умолчанию) с теми же фильтрами, что `GET /api/admin/submissions`: вердикт и статус — текущей проверки, группа — её **текущие** члены |
| `show <id>` | Посылка: ученик, контест, задача, язык, «с опозданием»; все проверки (причина, статус, вердикт, баллы, версия, актуальная, попытки, воркер, внутренняя ошибка) и тесты актуальной проверки — **включая скрытые** (это вид админа). `--json` — то же, что `GET /api/admin/submissions/<id>` |
| `rejudge --id <id>` | Перепроверить посылку (новая проверка, история сохраняется; [`QUEUE.md`](QUEUE.md)) |
| `rejudge --contest <slug> --problem <метка>` | Все посылки задачи контеста |
| `rejudge --contest-problem-id <id>` | То же по внутреннему id (для старого синтаксиса и скриптов) |
| `rejudge --problem-version <slug>@<версия>` | Все посылки всех задач контестов, закреплённых на этой версии (и скрытых) |
| `--verdicts WA,TL` | Только посылки с этими текущими вердиктами (не с `--id`) |
| `--dry-run` | Только посчитать, сколько посылок будет перепроверено (не с `--id`) |

Аудит: `submission.rejudge` (одна посылка), `submissions.rejudge` (пачка: фильтр и числа; до 4а.3b —
`contest_problem.rejudge` на каждую задачу). Консоль выполняет сразу; в API пачка — в два шага (`dry_run`, потом
`expect`).

### status — состояние установки

`judgectl status [--details]` (и `--json`), код выхода 1, если база недоступна или не на последней миграции. Всё, кроме блобов, берётся из того же `app/system.py`, что `GET /api/admin/system`:

* база и миграция (`alembic_version` против головы миграций в коде: «run the migrations», если отстаёт);
* воркеры онлайн и занятые, длина очереди и уровень загрузки;
* проверки версий задач (4а.4): сколько в очереди и идёт, сколько версий ждут (`pending_check`), последние проверки с
  итогом `failed` и **предупреждение** по каждой задаче неархивного контеста, закреплённой на `failed`-версии (посылки
  принимаются, но задачу стоит исправить и закрепить `ready`-версию);
* конфигурация публичного приложения (`JUDGE_SECRET_KEY`, `JUDGE_PUBLIC_ORIGIN`, порты) — те же проверки, что при
  его запуске; `JUDGE_TIMEZONE`;
* хранилище блобов: файлы, строки `blobs`; **файлы без строки** (остались от импорта, который не зафиксировался —
  ничего не удаляется, сборщик — модуль 6), **строки без файла** (файлы пропали из `JUDGE_BLOB_DIR` — тревога), строки,
  на которые ничего не ссылается.
* `--details` — для каждой строки без файла: кто на неё ссылается (`задача@версия test группа/тест (input|answer)`,
  `… program роль имя`, `… file путь`, `… uploaded zip`, `submission id (логин, контест метка)`) или «nothing refers to
  it». Так видно, остатки ли это модуля 3 (например, тесты `dev-sum@1`, записанные `dev_seed` в другой каталог блобов)
  или пропали файлы новых данных.

## Старое имя: `app.admin_cli`

`python -m app.admin_cli …` (синтаксис модуля 3) остаётся алиасом до модуля 6: переводит аргументы, пишет в stderr
`admin_cli is deprecated, use: judgectl …` и выполняет новые команды. На нём держится `deploy/dev/judge-dev admin …`.

| admin_cli | judgectl |
|---|---|
| `create-worker-token <имя> [--caps]` | `worker token create <имя> [--caps]` |
| `revoke-worker-token <имя>` | `worker token revoke <имя>` |
| `status` | `queue status` + `worker list` |
| `reap`, `judgements`, `events` | `queue reap`, `queue judgements`, `queue events` |
| `rejudge --submission <id> \| --contest-problem <id> [--verdicts …]` | `submission rejudge --id <id> \| --contest-problem-id <id> [--verdicts …]` |
