# Контесты

Задачи выдаются ученикам только через контесты (Р19); тренировочный архив — контест без даты окончания. Решения —
Р19–Р25, Р35 и §5.6 в [`MODULE_4A.md`](MODULE_4A.md); таблицы — [`DATA_MODEL.md`](DATA_MODEL.md).

| Где | Что |
|---|---|
| [`protocol/schemas/contest.schema.json`](../protocol/schemas/contest.schema.json) | JSON Schema для `contest.yaml` |
| [`backend/app/contests/spec.py`](../backend/app/contests/spec.py) | разбор `contest.yaml` и правила, которых нет в схеме |
| [`backend/app/contests/service.py`](../backend/app/contests/service.py) | `apply`, `pin`, состояния, коды приглашения, вступление, личный старт |
| [`backend/app/contests/access.py`](../backend/app/contests/access.py) | правила доступа — чистые функции (Р25) |
| [`contests-examples/`](../contests-examples) | примеры: архив-тренировка, олимпиада с личным таймером, урок с заморозкой |

Из веба — `PUT /api/admin/contests/<slug>` с тем же файлом в виде JSON ([`ADMIN_API.md`](ADMIN_API.md) §5.3).
Команды — `judgectl contest …` ([`JUDGECTL.md`](JUDGECTL.md)): `apply` (файл или stdin, `--dry-run`), `show` (с
кодом приглашения), `publish`, `archive`, `pin … --rejudge | --no-rejudge`, `code regenerate`, `participants`.
Посылку «как ученик» до API 4б делает `dev_seed --contest <slug> --label <метка>` (только dev): вступает с кодом
контеста, нажимает «Начать» в личном контесте и проходит `can_submit`; отказ правил останавливает его с причиной.

## 1. `contest.yaml`

Контест описывается файлом, его можно хранить в git; `apply` приводит контест к файлу и повторно ничего не меняет (Р35).

```yaml
format_version: 1
slug: olymp-7b-autumn
title: "Осенняя олимпиада, 7Б"
description: |
  Три задачи, 90 минут с момента нажатия «Начать».
starts_at: 2026-11-10 09:00        # без смещения — время JUDGE_TIMEZONE
ends_at: 2026-11-10 18:00
timing_mode: personal
personal_duration: 1h30m
scoring_mode: icpc
leaderboard: after_end
access: {mode: code}
languages: [python, cpp]
submit_cooldown_sec: 30
problems:
  - {label: A, problem: sum-of-two, version: 1}
  - {label: B, problem: pair-with-sum}
  - {label: C, problem: guess-number, points: 150}
```

| Поле | По умолчанию | Смысл |
|---|---|---|
| `slug`, `title` | обязательно | идентификатор (`[a-z0-9-]`) и название |
| `description` | пусто | Markdown для участников |
| `starts_at` | обязательно | начало; ISO 8601, без смещения — в `JUDGE_TIMEZONE`, `Z` или `+07:00` — как написано |
| `ends_at` | нет | конец; без него контест бессрочный (архив-тренировка) |
| `timing_mode` | `fixed` | `fixed` — общее окно `[starts_at, ends_at)`; `personal` — личный таймер |
| `personal_duration` | — | только и обязательно при `personal`: `90m`, `1h30m`, `2h`; больше нуля |
| `freeze_at` | нет | заморозка таблицы; нужен `ends_at`, внутри окна, не при `leaderboard: hidden`, не при `personal` |
| `scoring_mode` | `points` | `points` или `icpc`; `icpc_penalty_minutes` (20) — штраф за попытку |
| `leaderboard` | `hidden` | `hidden`, `visible`, `after_end` (после `ends_at`) |
| `access.mode` | `code` | `open` — кнопкой; `code` — по коду приглашения; `groups` — ученикам групп из `access.groups` без кода; `code_or_groups` — любой путь (§3). Ключ `join_policy` из 4а.2 больше не принимается, ошибка подсказывает замену |
| `access.groups` | нет | названия групп (классов, `judgectl group`), которым адресован контест; без учёта регистра; только и обязательно (хотя бы одна) при `groups` / `code_or_groups` |
| `allow_upsolving` | `true` | дорешивание после окна (посылки принимаются, в зачёт не идут) |
| `languages` | все | список разрешённых языков из включённых в системе |
| `submit_cooldown_sec` | 15 | пауза между посылками одного ученика |
| `max_submissions_per_problem` | нет | лимит зачётных посылок на задачу |
| `tests_after_end` | `false` | после окончания показать ученикам все тесты |
| `plagiarism_enabled` | `false` | флаг для будущего хука антиплагиата |
| `problems` | обязательно | `label` (`A`, `B1`; `[A-Z][A-Z0-9]{0,7}`), `problem` (slug), `version` (необязательно), `points` (переопределение итога задачи; баллы групп масштабируются пропорционально); сроки — ниже |
| `problems[].available_from` | нет | до этого момента (включительно — с него) задачи для ученика нет вовсе |
| `problems[].due_at` | нет | срок, включительно (§4, «Границы времени»); раньше `available_from` нельзя |
| `problems[].after_due` | `{statement: visible, submit: late}` | после эффективного срока: `statement` — `visible` / `hidden`; `submit` — `no` (отказ), `late` (в зачёт с отметкой), `yes` (как обычно). Дорешивание не трогается |
| `problems[].note_md` | нет | пояснение преподавателя к задаче в этом контесте (Markdown); видят ученики с доступом |

Продления сроков в файле **нет**: это оперативные действия (`judgectl extension`, §5), повторный `apply` их не трогает.

В файле нет состояния контеста и кода приглашения: их меняют команды (`publish`, `archive`, `code regenerate`),
иначе повторный `apply` откатывал бы публикацию, а код попадал бы в git. Даты YAML читаются как текст, кавычки не нужны.
Все ошибки файла выдаются разом.

## 2. `apply`

* Новый контест создаётся в состоянии `draft`; в режимах с кодом (`code`, `code_or_groups`) сразу получает код
  приглашения.
* **Группы** (К5): `apply` подключает группы из `access.groups` и отключает те, что из файла убраны. Неизвестная группа и
  архивная группа, ещё не подключённая к контесту, — ошибка (К6: архивную нельзя подключить). Группа, подключённая и
  потом заархивированная, остаётся в файле без ошибки, `apply` лишь предупреждает, что она не даёт доступа.
* Задача в контесте определяется **по задаче**, метка — её изменяемый атрибут: метки можно переставлять и менять.
* **Версия.** `version` указана — закрепляется она (только `ready`). Не указана — остаётся текущее закрепление, а у
  новой задачи берётся последняя `ready`. Если указанная версия отличается от закреплённой, а посылки по задаче уже
  есть, `apply` отказывает и подсказывает `judgectl contest pin <контест> <метка> <версия> --rejudge` (или
  `--no-rejudge`): смена версии с посылками — явное решение (Р22). Без посылок `apply` меняет версию сам.
* **Задача убрана из файла:** если по ней есть посылки — строка становится скрытой (`hidden`: ученики её не видят, в
  таблице её нет, посылки сохраняются), иначе удаляется.
* **Задача вернулась в файл:** снова видимой становится **последняя** скрытая строка этой задачи, если её версия
  совпадает с версией в файле (или версия в файле не указана); иначе создаётся новая строка, скрытые остаются
  скрытыми со своими посылками.
* Задача в архиве, задача без `ready`-версии, несуществующая версия, неизвестный язык — ошибка; все ошибки разом, и
  при ошибке не меняется ничего.
* **Предупреждения** — не ошибки: при переходе из режима без кода (`open`, `groups`) в режим с кодом снова начинает
  действовать код, который был у контеста раньше (он хранится, но не используется). `apply` об этом предупреждает и
  подсказывает `judgectl contest code regenerate <контест>`, если старый код мог разойтись. Отключение группы тоже
  предупреждает: её ученики теряют доступ, если не входили по коду (свои посылки и оценки они видят по-прежнему).
* **Сроки:** `apply` предупреждает, если `due_at` записан с минутой 59 без секунд (`23:59` — это 23:59:00, посылка в
  23:59:30 уже с опозданием; «до конца минуты» — `23:59:59`), если новый `due_at` не раньше существующих продлений (они
  больше ничего не дают) и если срок убран, а продления есть (они остаются, но ничего не значат; `judgectl extension
  list`). Время из `GET` приходит с секундами, поэтому отправленный обратно `spec` предупреждения не вызывает.
* Каждое изменение — строка в отчёте и в аудите `contest.apply`; без изменений аудит не пишется.

`pin` — сменить закреплённую версию задачи (только `ready`); с `--rejudge` все посылки задачи перепроверяются на новой
версии (новые проверки, история сохраняется, [`QUEUE.md`](QUEUE.md)). Аудит `contest.pin`.

## 3. Состояния, код, вступление, старт

* `draft` — видит только админ; `published` — видят ученики (контест режима `groups` — только ученики его групп);
  `archived` — только для чтения и только участникам, у которых есть доступ. `publish` / `archive` (аудит
  `contest.publish` / `contest.archived`).
* **Код приглашения** — 6 символов из `ACDEFGHJKMNPQRTUVWXY3479` (без похожих 0/O, 1/I/L, 2/Z, 5/S, 8/B), вводится
  в любом регистре, пробелы и дефисы игнорируются. `code regenerate` выдаёт новый (аудит `contest.code_regenerate`).
* **Режим доступа** (`access_mode`, D-021): `open` — все ученики; `code` — по коду приглашения; `groups` — ученики,
  которые **сейчас** состоят в неархивной группе, подключённой к контесту, без кода; `code_or_groups` — любой из двух
  путей. Доступ к группе считается по текущему составу: ученик, добавленный в группу позже, получает доступ сразу,
  убранный (или при архивации и отключении группы) теряет условия и сдачу, но свои посылки и оценки видит всегда.
* **Первый вход** (Р23): только опубликованный контест; после окончания — только при `allow_upsolving`. Он создаёт
  участие и запоминает путь — `joined_via`: `open`, `group` (ученик подключённой группы входит без кода, даже если
  ввёл код) или `code`. Сам по себе доступ даёт только `code`; `group` действует, пока ученик в группе, `open` —
  пока контест открыт. Уже участник с `joined_via` не `code` (убран из группы или вошёл, пока контест был открыт),
  который вводит верный код в режиме с кодом, получает `joined_via = code` (ответ `rejoin_with_code`) и снова доступ.
  Вход отдельно от личного старта.
* **Личный старт** (Р21, `personal`): один раз, внутри `[starts_at, ends_at)`, только с доступом; личное окно —
  `[started_at, min(started_at + personal_duration, ends_at))`. Без `ends_at` — тренировка на время: начать можно в
  любой день после `starts_at`.

## 4. Доступ (Р24, Р25, D-020…D-023)

Чистые функции в `access.py`; эндпоинты 4б и админского API вызывают только их. То, что требует базы, передаёт
сервис: `in_group` (ученик сейчас в неархивной группе контеста) и `extensions` (сроки его личного продления и продлений
его текущих групп по этой задаче). Время `now` — серверное, UTC, момент получения запроса (до чтения тела). Админ может
всё (его посылки не идут в зачёт и не бывают «с опозданием»). Для ученика:

| Функция | Правило |
|---|---|
| `contest_window_for` | `fixed`: `[starts_at, ends_at)`; `personal`: личное окно после старта, до старта — нет окна |
| `has_access` | по режиму (§3): `open` — всем; `code` — участие с `joined_via = code`; `groups` — `in_group`; `code_or_groups` — любое |
| `can_view_contest` | `published` (режим `groups` — только с доступом); `archived` — участнику с доступом; `draft` — никогда |
| `can_see_own_results` | свои посылки и оценки: всегда, если ученик участвовал и контест не `draft` — без доступа, после срока, в архиве |
| `can_enter` | см. §3; ответы: `not_published`, `already_joined`, `rejoin_with_code`, `contest_over`, `wrong_code`, `no_access`; в `joined_via` — путь входа |
| `can_start` | см. §3; ответы: `not_personal`, `not_participant`, `no_access`, `not_started_yet`, `contest_over`, `already_started` |
| `problem_listed` | задачи нет вовсе (ни метки, ни названия), если она скрыта или раньше `available_from` |
| `effective_due` | максимум из `due_at` и продлений; без `due_at` срока нет (продлевать нечего) |
| `can_view_problem` | участнику с доступом, задача есть (`problem_listed`), его окно началось (после конца — при дорешивании); после срока — только при `after_due_statement: visible` |
| `can_submit` | см. ниже |
| `can_see_leaderboard` | участнику с доступом: `visible` — всегда, `after_end` — после `ends_at`, `hidden` — никогда |
| `leaderboard_cutoff` | с `freeze_at` до `ends_at` ученик видит таблицу на момент заморозки, админ — живую; после конца — живая |
| `visible_tests` | содержимое только открытых групп; все — при `tests_after_end` после `ends_at` |

`can_submit` проверяет по порядку:
1. состояние `published` (`not_published`), участие (`not_participant`), доступ (`no_access`), скрытость задачи
   (`problem_hidden`), язык (`language_not_allowed`);
2. **окно контеста** — раньше срока задачи: до окна `not_started_yet`, личный контест без старта `press_start`, в окне —
   посылка **в зачёт**, после окна — **дорешивание** (не в зачёт) или `contest_over` без `allow_upsolving`. Закончившийся
   контест без дорешивания не принимает посылки, каким бы ни был срок задачи;
3. `available_from` (`not_available_yet`);
4. **срок задачи** — только для зачётных посылок: после эффективного срока `after_due_submit` решает — `no` → отказ
   `deadline_passed`, `late` → принять в зачёт с отметкой `late` (ответ `late`), `yes` → принять как обычную.
   **Дорешивание сроки не трогают** (В3): после окна посылка не в зачёт и без `late`, что бы ни говорила политика;
   закрыть дорешивание — `allow_upsolving: false`. Личный таймер и срок действуют одновременно: что раньше, то и
   побеждает (кончилось личное окно — дорешивание; прошёл срок внутри окна — политика срока);
5. лимит зачётных посылок (`submission_limit`; посылки с опозданием считаются, дорешивание — нет) и пауза (`cooldown`
   с `retry_after_s`).

`late` фиксируется при приёме и потом не пересчитывается: продление, выданное позже, старые отметки не меняет.

**Приём посылки** — только через `service.submission_decision(db, user, contest, contest_problem, now)`: он собирает
участие, `in_group`, продления (`extensions_for`), последнюю посылку и число зачётных и вызывает `can_submit`. `now`
вызывающий берёт **один раз**, в момент получения запроса, до чтения исходника; посылка получает `created_at = now` и
`late = decision.late`. Так делает `dev_seed --contest` и так будет делать API 4б.
Строка участия блокируется (`SELECT … FOR UPDATE`) до подсчёта лимита и паузы, а посылка записывается в той же
транзакции: два одновременных запроса ученика идут друг за другом, и второй видит первый (тест — две параллельные
посылки при паузе 15 с, принимается одна).

**Список контестов ученика (для 4б).** В список входит контест, для которого `can_view_contest` **или**
`can_see_own_results`. Контест, попавший в список только по второму условию (ученика убрали из группы, режим сменился,
группу заархивировали), открывается в режиме «только мои результаты»: свои посылки и оценки — да; условий, сдачи и
таблицы результатов — нет. Строка теста: убранный из группы ученик — `can_view_contest = False`,
`can_see_own_results = True`.

**Сервис** (`service.py`, `groups.py`): `access_inputs(db, contest, user)` даёт `(participation, in_group)` для функций
выше; `enter` — первый вход (и смена `joined_via` на `code` по верному коду, аудит `contest.rejoin_with_code` от имени
ученика, без самого кода); `start` — личный старт. Ученик всегда приходит объектом `User` из сессии; идентификаторов
пользователя, группы или участия из запроса эти функции не принимают (тест подмены — `tests/pg/test_groups_pg.py`).

### Границы времени

| Граница | Правило | Почему |
|---|---|---|
| окно контеста `[starts_at, ends_at)` | `starts_at` — уже в окне, `ends_at` — уже нет (в этот момент посылка — дорешивание) | конец контеста — момент, когда «время вышло»; так же устроены личное окно и заморозка |
| `available_from` | включительно: в этот момент задача уже есть | «открывается в 10:00» — значит в 10:00 |
| срок `due_at` (с продлениями) | включительно: посылка в срок, если время приёма ≤ эффективного срока | срок урока — «сдать до такого-то времени», и последняя секунда этого времени ещё в срок |

Границы окна и срока разные намеренно, и тесты проверяют обе (строки «за микросекунду до», «ровно», «через
микросекунду»). Время сравнивается с точностью до микросекунды: `due_at: 2026-11-10 23:59` означает 23:59:00, и
посылка в 23:59:30 уже с опозданием. «До конца дня» пишется как `23:59:59` или `00:00` следующего дня.

Таблица случаев — `tests/test_contest_access_units.py` (матрица «режим × ситуация ученика», смена режима, границы
срока для `no` / `late` / `yes`, продления, личный таймер со сроком, конец контеста раньше срока).

## 5. Продления сроков (D-023, `contests/deadlines.py`)

Продление — более поздний срок одной задачи контеста для **одного ученика** или **одной группы**. Эффективный срок
ученика — максимум из `due_at`, его личного продления и продлений групп, в которых он **сейчас** состоит (архивная
группа ничего не продлевает; убранный из группы теряет её продление).

* Только позже `due_at`: продление не позже срока и продление задачи без `due_at` — отказ (`extension_not_later`,
  `no_deadline`). Только ученику (`not_a_student`) и только неархивной группе (`group_archived`).
* Повторное продление для того же ученика или группы **заменяет** срок (В7); прежний срок — в аудите
  (`contest.extension_add`, поле `replaced`). Удаление — `contest.extension_remove`.
* Уже принятые посылки продление не меняет: отметка `late` у них остаётся.
* Команды: `judgectl extension add | list | remove` ([`JUDGECTL.md`](JUDGECTL.md)); в админском API —
  `…/problems/{label}/extensions` ([`ADMIN_API.md`](ADMIN_API.md) §5.5).
